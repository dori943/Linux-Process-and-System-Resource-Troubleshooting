# [Bug] OOM Crash - 메모리 누수로 MEMORY_LIMIT(80MB) 초과, MemoryGuard 가 SIGKILL 로 자기 종료

> **심각도**: Critical | **유형**: Memory Leak / OOM | **상태**: 분석 완료

## 1. Description (현상 설명)

- **무슨 일이 발생했는가?** `agent-leak-app` 을 실행하면 약 12초 뒤 터미널에 `SELF-TERMINATED (Memory Limit Exceeded)` 가 찍히며 프로세스가 사라진다. 종료 코드는 137 (128+9 = SIGKILL).
- **언제, 어떤 조건에서?** `MEMORY_LIMIT=80` 으로 실행할 때 매번 재현된다. 워커 프로세스의 RSS 가 3초마다 약 25MB 씩 증가해 최대 92.6MB 에 도달한 직후 종료된다.

실행 환경 (Before):
```
MEMORY_LIMIT=80
CPU_MAX_OCCUPY=50
MULTI_THREAD_ENABLE=false
실행 시각: 2026-10-21 20:33:49   워커 PID: 60
```

## 3. Root Cause Analysis (원인 분석)

**현상 분석.** 앱 로그의 `[MemoryWorker] Current Heap` 과 OS 가 측정한 RSS 가 같은 기울기(+25MB / 3초)로 오른다. 할당한 객체에 대한 참조가 계속 남아 GC 가 회수하지 못하는 전형적인 힙 메모리 누수(Memory Leak) 패턴이다. CPU 사용률은 낮게 유지되므로 연산 부하와는 무관하다.

**앱의 보호 정책(MemoryGuard).** 힙이 `MEMORY_LIMIT` 에 도달하는 순간 `Memory limit exceeded` → `Self-terminating process` 로그를 남기고 자기 자신에게 SIGKILL 을 보낸다. 종료 코드 137 과 터미널의 `Killed` 가 그 증거다. SIGKILL 은 프로세스가 받아서 처리할 수 없고 커널이 즉시 제거하므로 정리 작업(cleanup) 없이 사라진다.

**OS 동작 원리.** 커널은 프로세스에 가상 주소 공간을 주고 실제로 쓴 페이지만 물리 메모리(RSS)에 올린다. 누수가 계속되면 free 메모리가 줄고, 페이지 캐시 축소 → 스왑 → 시스템 전체 지연으로 번진다. 끝까지 가면 커널의 OOM Killer 가 `oom_score` 가 높은 프로세스를 SIGKILL 하는데, 누수 프로세스가 아닌 다른 서비스가 희생될 수 있다. MemoryGuard 는 그 전에 자기 자신을 먼저 종료해 시스템 전체 장애를 막는 앱 레벨 안전장치다. (이 실행에서는 앱이 먼저 종료되어 `dmesg` 에 커널 OOM 기록이 남지 않는다.)

## 4. Workaround & Verification (조치 및 검증)

**조치.** 다른 환경변수는 그대로 두고 `MEMORY_LIMIT` 만 80 → 300 으로 상향해 재실행했다.

```bash
export MEMORY_LIMIT=300   # Before: 80
```

**Before & After (실측).**

| 구분 | 환경변수 | 생존 시간(초) | 결과 | 종료 코드 | 최대 RSS(MB) |
|---|---|---|---|---|---|
| Before | MEMORY_LIMIT=80, CPU_MAX_OCCUPY=50, MULTI_THREAD_ENABLE=false | 12 | 스스로 종료 | 137 (128+9, SIGKILL) | 92.6 |
| After | MEMORY_LIMIT=300, CPU_MAX_OCCUPY=50, MULTI_THREAD_ENABLE=false | 50+ (관찰 종료 시점까지 생존) | 관찰 종료까지 생존 (수동 kill) | - (종료 안 됨) | 292.9 |

마지막 로그 한 줄:

- Before: `2026-10-21 20:34:00,876 [CRITICAL] [MemoryGuard] Self-terminating process 60 to prevent system instability.`
- After: `2026-10-21 20:35:05,830 [INFO] [CpuWorker] Cooldown complete (5.00%). Resuming load increase...`

종료 배너(터미널 출력):

- Before: `>>> [SYSTEM] SELF-TERMINATED (Memory Limit Exceeded) <<<`
- After: `>>> [SYSTEM] MEMORY RECOVERED (Cache Cleared) <<<`

**해석.** 80MB 에서는 12초 만에 SIGKILL 되었지만, 300MB 에서는 임계치 도달 시 `Memory Cache Flushed. Process Stabilized.` 와 함께 힙을 비우고 계속 동작한다 (RSS 최대 292.9MB 후 다시 감소). 즉 상향 조정으로 프로세스가 관찰 시간 내내 생존했다. 다만 누적 자체는 그대로이므로 임시 조치이며, 근본 해결은 코드에서 참조를 끊거나(`del`/`pop`) 캐시 크기 상한을 두는 리팩터링이다.
